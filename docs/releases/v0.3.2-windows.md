# Remote VoiceIME 0.3.2 · Windows alpha

构建 12，2026-11-10。Windows 修订版，修复 [0.3.1](https://github.com/jacksonlin-infra/remote-voiceime/blob/main/docs/releases/v0.3.1-windows.md) 无法自动识别 UU 远程 4.x 的问题（[#1](https://github.com/jacksonlin-infra/remote-voiceime/issues/1)）。本次发布仅包含 **Windows x64**；macOS 当前发布仍为 [0.3.0](https://github.com/jacksonlin-infra/remote-voiceime/releases/tag/v0.3.0-macos)（共享版本元数据已为 0.3.2 / 12，macOS 未重新构建发布）。

## 修复

- **在 UU 窗口按右 Ctrl 没有反应。** UU 远程 4.x 的客户端与会话窗口进程为 `GameViewer.exe`，0.3.1 只自动识别旧进程名 `UURemote.exe`，UU 窗口不被当作远控目标，按键全部放行，诊断日志为 `hotkey ignored: foreground=GameViewer … capture=none`。在设置中手动选过 UU 主程序的电脑不受影响，所以此前未发现。现在默认识别 `GameViewer.exe` 与 `UURemote.exe`，无需手动选择；准备清单的“正在运行”检测同样识别 `GameViewer.exe`。已手动选择的路径继续有效。

操作方式、设置与界面与 0.3.1 相同。

## 下载与校验

| 文件 | 用途 |
| --- | --- |
| `RemoteVoiceIME-0.3.2-win-x64-setup.exe` | 安装程序（推荐，可直接覆盖 0.3.x） |
| `RemoteVoiceIME-0.3.2-win-x64.zip` | 免安装版 |
| `SHA256SUMS.windows-win-x64.txt` | SHA-256 校验 |

安装前从托盘退出旧版本。安装后在「设置 → 运行环境与诊断」底部核对 **0.3.2（构建 12）**。安装程序与程序均未做发布者代码签名，SmartScreen 可能提示未知发布者。目标为 Windows 10 / 11 x64，内置 .NET 运行时；只为当前用户安装，无需管理员权限，设置沿用。

## 验证范围

- 141 项 Windows 核心检查通过，其中新增：`GameViewer.exe` 在未手动选择时按 UU 识别（含 `Qt51512QWindowIcon` / `Qt51519QWindowIcon` 窗口类与大小写差异），被控端进程 `GameViewerServer.exe` 不被识别。
- 在运行 UU 4.45.0 的 Windows 上核对：UU 进程名为 `GameViewer.exe`，与问题报告一致。
- 本次未改动界面，未重新生成截图。原生 UI 预览（`--preview-ui`）在当前验证机的 150% 缩放下停在浮条宽度检查，已发布的 0.3.1 在同一台机器上同样停在此项，属于预览检查按 100% 缩放编写，不是本次改动引起。
- 识别结果与此前手动选择 `GameViewer.exe` 时相同，该配置在 0.3.x 的 UU 日常使用中已验证；本次发布前未在清空手动路径后重新做端到端按键实测。
